有些场景下，把数据发给第三方 API 这条路根本走不通：金融、医疗、涉密单位，或者单纯是合规要求。

这条路线讲的是**私有化落地**的完整判断链：先确认是否真的需要，再解决怎么部署，最后才考虑要不要微调。

**顺序很重要，而且绝大多数人搞反了。**

正确的顺序是：**评估 → 部署 → 微调**。

搞反的典型表现是先花几万块买显卡，或者一上来就张罗微调数据集——结果发现用 API 加一套 RAG 就能解决问题，成本还更低。

这篇路线的核心其实是一个决策问题：**知识不足用 RAG，行为不对才微调**。理解这条分界线，能帮你避开私有化落地里最贵的那几个坑。

如果你还不确定自己的问题属于哪一类，先回到[大模型应用开发](/paths)那条路线把 RAG 和提示工程过一遍，通常就清楚了。
